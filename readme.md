## Общее описание

В целях выполнения финальной работы я рассматривал различные варианты создания игры змейка, но задача что бы змейка могла двигаться в любом направлении достаточно не проста.  
К тому же добавляется требование расчета перемещения с помощью Афинных преобразований (достаточно распространенных надо сказать).  
Исходя из вышесказанного я пришел к мнению, что змейка должна уметь поворачиваться на любой угол, но обычное управление с клавишей "стрелки" не позвроляет реализовать весь задуманный функционал. В итоге я взял комплнент ***QDial***, который позволяет как оставить возможность управлять "стрелками", но добавляет возможности:  
- управлять с помощью PgUp / PgDown;
- управлять поворотом "ручки" мышью, для выбора любого значения угла.

Но в таком случае игра уже не могла быть размещена в единственном виджете!

## Компоновка и управление игрой в классе ***Snake***

Базовый виджет ***Snake*** стал платформой (хотя легко мог быть и *QMainWindow*, но был оставлен типом *QWidget* для обеспечения требований задания), на которой с помощью ***QVBoxLayout*** были вертикально размещены 3 виджета:  
- ***GameField*** - само игровое поле и по совместительству по сути класс, содержащий всю логику игры "Змейка"
- ***QLCDNumber*** - для вывода угла поворота ручки. Ну интересно же знать направление :)
- ***QDial*** - ручка управления направлением змейки.

По сути в самом классе ***Snake*** кроме описания виджетов, которые будут внедрены на этот виджет, добавлен единственный слот обработки сигнала изменения положения ручки ***QDial***  
```c++
public slots:
    void changeDial(int value);
```
. В рамках которого:  
- меняется показание направления в ***QLCDNumber***  
```c++
m_lcdnumber->display(value);
```
- в классе ***GameField*** меняется значение переменной направления движения с использованием сеттера. Так как в самом виджете ***QDial*** знавчения направления заданы в градусах от -180 до +180, то эти значения предварительно переводятся в радианы с использованием директивы `#define _USE_MATH_DEFINES` и библиотеки `#include <cmath>`, в которых беру значение PI.   
```c++
m_gameField->setAngle(value * (M_PI / 180.0));
```
Так же можно видеть закоментированное указание, что класс ***GameField*** дружественный - в целях более простого доступа к данному классу, но это и не потребовалось, все осталось в рамках классического ООП.

## Логика игры "Змейка"

В большей части игра стандартная, взята из прошлого задания. Потому опишу основные изменения, которые были внесены (ну кроме того, что класс игры теперь называется по другому ***GameField***).

1. Новый параметр ***directAngle*** в котором хранится текущее значение угла направления в приватной части класса. И соответственно публичный сеттер 
```c++
void setAngle(double angle);
```
для изменения значения угла из класса ***Snake*** после поворота ручки ***QDial***.  
2. Соответственно исключены булевые параметры для направления "вверх" / "вправо" / "вниз" / "влево".  
3. В методе ***initGame()*** добавлена установка начального направления ***directAngle*** на 0. А также для усложнения добавлен новый метод ***locateWalls()***, в котором инициализируются координаты двух стен - горизонтальной и вертикальной.

void GameField::initGame()

4. Добавлен новый метод `void affineRotateMove(double, double);` отвечающий за Афинные преобразования (матрица поворота и перемещения).  
По сути поворот определяется матрицей
$$
\begin{bmatrix}
\cos{\phi} & -\sin{\phi} \\
\sin{\phi} & \cos{\phi} \\
\end{bmatrix}
$$
Но учитывая, что экранный `Y` направлен вниз, то знаки во второй колонке приходится менять. Соответственно для случая экрана матрица будет:
$$
\begin{bmatrix}
\cos{\phi} & \sin{\phi} \\
\sin{\phi} & -\cos{\phi} \\
\end{bmatrix}
$$
И здесь надо помнить, что поворот происходит вокруг начала системы координат. Мне же нужен поворот от предыдущей точки, или можно сказать относительнгый поворот на длину точки *DOT_SIZE*. Я для себя определил, что нулевое направление у меня вверх, соответственно единичный вектор смещения змейки у меня будет:
$$
\begin{bmatrix}
0 & \text{DOT\_SIZE} \\
\end{bmatrix}
$$
Смещение же так не определить, т.к. необходима гомогенная матрица. С учетом приведения поворота и смещения (по сути прибавления вектора перемещения к предыдущей координате головы змейки) к гомогенной матрице получаю:
$$
\begin{bmatrix}
0 & \text{DOT\_SIZE} & 1 \\
\end{bmatrix}
\cdot
\begin{bmatrix}
\cos{\phi} & \sin{\phi} \\
\sin{\phi} & -\cos{\phi} \\
x[0] & y[0] \\
\end{bmatrix}
$$
Тогда сам метод будет:
```c++
void GameField::affineRotateMove(double dx=0, double dy=DOT_SIZE)
{
    x[0] = dx * std::cos(directAngle) + dy * std::sin(directAngle) + x[0];
    y[0] = dx * std::sin(directAngle) - dy * std::cos(directAngle) + y[0];
}
```
5. Логично меняется метод `move()`, т.к. теперь приращения не задаются, а происходит вычисление поворота и перемещения через матрицу:
```c++
void GameField::move()
{
    for (int z = dots; z > 0; z--)
    {
        x[z] = x[(z - 1)];
        y[z] = y[(z - 1)];
    }
//////////////////////////
    affineRotateMove();
//////////////////////////
}
```
6. Небольшие изменения внес в метод определения коллизий. Т.к. управление немного сложнее стало, то отключил контроль границ, и теперь "змейка" как бы проходит насквозь с другой стороны. Коллизия, вызывающая конец игры, осталась только на самопересечение.     if (y[0] >= B_HEIGHT) { y[0] = 0; }

9. Добавлен метод инициализации координат для создания 2-х стен.
```c++
void GameField::locateWalls()
{
    int l = WALL_MIN + QRandomGenerator::global()->generate() % (WALL_MAX - WALL_MIN);
    int h = QRandomGenerator::global()->generate() % (RAND_POS - l);
    int v = QRandomGenerator::global()->generate() % RAND_POS;
    for(size_t i = 0; i < l; i++)
    {
        wallH_x.push_back(h * DOT_SIZE + i * DOT_SIZE);
        wallH_y.push_back(v * DOT_SIZE);
    };

    l = WALL_MIN + QRandomGenerator::global()->generate() % (WALL_MAX - WALL_MIN);
    h = QRandomGenerator::global()->generate() % RAND_POS;
    v = QRandomGenerator::global()->generate() % (RAND_POS - 1);
    for(size_t i = 0; i < l; i++)
    {
        wallV_x.push_back(h * DOT_SIZE);
        wallV_y.push_back(v * DOT_SIZE + i * DOT_SIZE);
    };
}
```
